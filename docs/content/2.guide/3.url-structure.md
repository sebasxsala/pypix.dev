pypix.dev supports PyPI-style package URLs and simpler alternatives.

## Use PyPI-style URLs

Use PyPI project names and versions:

| PyPI URL                         | pypix.dev equivalent                                                           |
| -------------------------------- | ------------------------------------------------------------------------------ |
| `pypi.org/project/requests/`     | [`pypix.dev/package/requests`](https://pypix.dev/package/requests)             |
| `pypi.org/project/fastapi/`      | [`pypix.dev/package/fastapi`](https://pypix.dev/package/fastapi)               |
| `pypi.org/project/pydantic/2.0/` | [`pypix.dev/package/pydantic/v/2.0`](https://pypix.dev/package/pydantic/v/2.0) |
| `pypi.org/search/?q=django`      | [`pypix.dev/search?q=django`](https://pypix.dev/search?q=django)               |

::tip
PyPI route compatibility is a migration target. Keep behavior explicit when changing route redirects.
::

## Use simpler URLs

pypix.dev also supports shorter, cleaner URLs:

| Pattern                | Example                                           |
| ---------------------- | ------------------------------------------------- |
| `/<package>`           | [`/requests`](https://pypix.dev/requests)         |
| `/<package>@<version>` | [`/pydantic@2.0`](https://pypix.dev/pydantic@2.0) |

## Understand URL limitations

Some inherited npm routes are not PyPI concepts and need redesign:

| URL Pattern                  | Status                           |
| ---------------------------- | -------------------------------- |
| `/package/<name>/access`     | Needs PyPI account-flow redesign |
| `/package/<name>/dependents` | Needs a Python dependency index  |
| `/settings/*`                | Not supported                    |
